# Query Understanding and Rewriting

## Query normalization
User questions may contain spelling variation, abbreviations, conversational wording, or unnecessary phrases. Normalization can standardize whitespace, casing, and selected punctuation before retrieval. It should not remove meaningful identifiers, numbers, negation, or domain-specific terms.

## Query rewriting
A query rewrite expresses the same information need using alternative terms or a clearer structure. It can help when the user's wording differs from the vocabulary used in the corpus. Rewrites may be generated by rules, dictionaries, or a language model. A rewrite should preserve the original intent and must not introduce assumptions that were not present in the question.

## Multi-query retrieval
A system can create several query variants and retrieve candidates for each one. The candidate lists can then be merged or fused. This can improve recall when one wording misses relevant passages, but it also increases retrieval cost and may add noise. Evaluation should compare the original query baseline with rewritten or multi-query retrieval while holding the corpus, labels, and final result count constant.

## Safety and observability
Keep the original user query alongside any rewritten variants so that results can be audited. Do not treat retrieved text as instructions for rewriting. Log transformations in a privacy-conscious way and avoid storing sensitive query content unnecessarily.
